# UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One consistent button/field/image-picker/date-picker system and motion language across the admin app and public site, plus the Works multi-category, Photos end-date removal and Create-person bug fixes.

**Architecture:** Tokens + base CSS define sizes and motion; small shared components (`Field`, `DatePicker`, `NumberField`, `ImageDropzone`, `Reveal`, `Skeleton`) replace per-page variants; one migration (V16) moves work categories to a join table and drops `taken_until`; then every page is passed over against the spec's rules.

**Tech Stack:** React 19 + TS + Vite, Radix, `motion` 14, new `react-day-picker`; Spring Boot + Flyway (Oracle/H2).

**Spec:** `docs/superpowers/specs/2026-11-11-ui-polish-design.md`

## Global Constraints

- Branch `feat/ui-polish` (worktree `.claude/worktrees/ui-polish`, already created from main `0d67bab`). One PR at the end. After each group of tasks below marked **[checkpoint]**, commit and add a PROGRESS.md entry in its own commit.
- Control heights only 32 / 40 / 48 px; fields 40 px (48 px only for the Get Engsub link input); radius 8 px; spacing values only 4 8 12 16 24 32 48 64; durations only the `--dur-*` tokens; easings only `--ease-out` / `--ease-in-out`.
- Brand: orange `#F39A42` actions, purple `#D9A1D9` state/hover/focus, red only delete/errors. UI copy English.
- Dates stay `yyyy-mm-dd` strings end to end; display `dd/MM/yyyy` in pickers, `9 Nov 2026` in lists (existing `formatDay`).
- Pin new npm dependencies to an exact version like the others in `package.json`, a release at least two weeks old.
- Tests: `mvn test -Dskip.npm`, `cd frontend && npm test` (compare file count with `find src -name "*.test.ts*" | wc -l`), `mvn verify -Poracle -Dskip.npm` for V16. `npm ci` only inside the worktree. Never `git add -A` (tsbuildinfo). No merge, deploy or Publish.
- Respect `prefers-reduced-motion` everywhere.

## Review Focus

1. **Forms inside portals submitting outer forms** (PersonPicker create, any popover/dialog form opened from inside a `<form>`): must never trigger the outer submit → Task 7 test + audit list.
2. **Release date cleared** → saved as `null` and shown as Coming Soon, sorted first; DatePicker never shifts the day in `America/Los_Angeles` or `Asia/Bangkok` → Task 3 + Task 7 tests.
3. **Old works with one category** keep it after V16 and old exported JSON is regenerated with `categories` → Task 6 test (migration on seeded data).
4. **Ctrl+V on a page with two dropzones** (e.g. Work editor cover + person avatar dialog) pastes only into the focused/open one → Task 4 test.
5. **Keyboard users:** every new control reachable and operable (Tab, Enter/Space, Esc closes popovers, arrows in the calendar) with visible focus ring → Tasks 3–5 tests.
