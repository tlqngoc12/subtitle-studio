# Profile Emi, Bonnie, EmiBonnie Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Menu **Profile** với 3 profile cố định (EmiBonnie, Emi, Bonnie), nội dung là danh sách khối tự do (6 loại), sửa ngay trên trang; ảnh upload vào `./data/media/`.

**Architecture:** Backend package `com.subtitlestudio.profile`: migration Flyway `V2__profiles.sql` (4 bảng `T_*`), entity JPA, `ProfileBlockValidator` thuần, `MediaService` lưu file theo id, `ProfileService` + 2 controller REST. Frontend: `src/api/profiles.ts`, trang `ProfilePage` với chế độ xem/sửa, component theo loại khối trong `src/components/profile/`.

**Tech Stack:** Java 21, Spring Boot 3.5, Spring Data JPA, Flyway, H2 `MODE=Oracle` / Oracle Free 23ai, Testcontainers; React 19 + Vite + TypeScript, Vitest + RTL, `react-markdown`, `yet-another-react-lightbox`, `@fontsource/noto-sans-thai`, `lucide-react`.

**Spec:** [docs/superpowers/specs/2026-11-03-profiles-design.md](../specs/2026-11-03-profiles-design.md)

## Global Constraints

- Làm trên worktree `../subtitle-studio-profiles`, nhánh `profiles` (giống Oracle), merge fast-forward vào `main` khi xong.
- TDD: test trước → chạy thấy FAIL đúng lý do → code tối thiểu → PASS. Trước khi báo xong mỗi task chạy **toàn bộ** `mvn -q test -Dskip.npm` (backend) và/hoặc `cd frontend && npm test` (frontend).
- Schema chỉ do Flyway tạo; Hibernate `validate`. Không sửa `V1__init.sql`. `V2__profiles.sql` được sửa tự do cho tới khi push.
- Bảng mới có tiền tố `T_`; mọi `id` là sequence `INCREMENT BY 50` + `allocationSize = 50`; cột số nguyên dùng `${bigint}`/`${int}`; timestamp `TIMESTAMP(6) WITH TIME ZONE` (như V1); chuỗi `VARCHAR2(n CHAR)`.
- **Đổi tên cột so với spec:** `T_PROFILE_BLOCK_ITEM.value` → `item_value` (`VALUE` là từ khóa của H2). JSON vẫn là `value`.
- Oracle lưu `''` thành NULL: mọi chuỗi tùy chọn được `strip()`, rỗng → `null`; chuỗi bắt buộc rỗng → lỗi validator.
- Test không tạo file trong `./data` (dùng `@TempDir` / `@DynamicPropertySource` thư mục tạm). `@SpringBootTest` kèm `@ActiveProfiles("test")`.
- `toLowerCase`/`String.format` truyền `Locale.ROOT`.
- Frontend: truy vấn theo role/label; nút chỉ có icon có `aria-label` + `title`; icon `lucide-react`; chuỗi tiếng Việt; version package cố định (không `^`), commit `package-lock.json`.
- Giới hạn: ảnh ≤ 10 MB (jpeg/png/webp/gif, nhận diện bằng magic bytes); `.srt` Vietsub vẫn ≤ 5 MB; `title` ≤ 200, `caption` ≤ 500, `label` ≤ 200, `value` ≤ 1000, `body` ≤ 100.000 ký tự, ≤ 50 item/khối.

## Review Focus

1. **Upload Vietsub `.srt` 6 MB sau khi nâng multipart lên 10 MB** → vẫn bị từ chối `FILE_TOO_LARGE` 413, không lọt vào parser. (Task 2, `rejectsSrtOver5Mb`)
2. **Sửa khối IMAGE đổi sang ảnh khác, hoặc lưu bị lỗi validator** → ảnh cũ chỉ bị xóa (dòng + file) khi lưu thành công; lưu lỗi thì ảnh cũ còn nguyên. (Task 4, `replacingImageDeletesOldMediaAfterCommit`, `failedUpdateKeepsOldMedia`)
3. **Link nhúng người dùng dán thật**: `youtu.be/ID?t=30`, `youtube.com/watch?v=ID&list=…`, `open.spotify.com/intl-vi/track/ID?si=…`, và dán lại chính URL nhúng khi sửa → đều được nhận và chuẩn hóa. (Task 3, `EmbedUrlResolverTest`)
4. **Markdown chứa `<script>`, `<img onerror>`, `[x](javascript:alert(1))`** → không thành phần tử/handler thật, link `javascript:` bị vô hiệu. (Task 5, `markdownIsNotExecuted`)
5. **Chữ Thái + emoji + tiếng Việt dài trong `body` CLOB và `label`** → lưu và đọc lại nguyên vẹn trên Oracle. (Task 7, `storesThaiEmojiMarkdownClob`)
